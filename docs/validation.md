## Dawnwalker startup correction — HappyCheats 0.3.11

Experimental trainer **0.1.1** corrects the loader profile behind the observed startup failure. Binary inspection showed that UE4SS incorrectly resolved `ProcessLocalScriptFunction` to executable RVA **`0x3904B40`**, the MSVC stack-cookie checker, and installed a script-dispatch hook there. A diagnostic minidump of a hung launch showed multiple threads blocked in the runtime hook's mutex path. The Dawnwalker profile now disables this unused script hook and other unused optional hooks, retaining **EngineTick** and **UObjectProcessEvent**. See [startup diagnosis and evidence](dawnwalker-startup.md).

The trainer also replaces repeated whole-object player discovery with player-construction notifications and a list bounded to **16 candidates**. Constructor callbacks retain references only; later game-thread polls validate possession, authority, ownership and liveness. Candidate overflow keeps the trainer unavailable until restart instead of selecting from an incomplete list. One persistent **250 ms game-thread timer** replaces the asynchronous polling handoff. The loader configuration explicitly selects Unreal **5.5**, retains its engine-tick scheduler, and the trainer publishes an initial heartbeat plus first-poll diagnostics before player evaluation.

Offline Lua validation passed **375 assertions** against the actual source scripts: **231 bindings**, **92 startup/mailbox/hotkey**, and **52 protocol** assertions. Loaded DataTable rows did not establish cache readiness; a constructor can expose level 1 and enabled progression while that cache is empty. The existing key signed an unchanged 0.3.12 recovery feed, and the known 0.3.12 EXE was restored while correcting the path. The 0.3.13 signed archive was preserved and never overwritten.
